BCF Mobile UX · spec v1

Mobile gesture contract

The mobile reading mode of the Celestial Forge visualization assumes a shared touch vocabulary. This document fixes the exact gestures, thresholds, hit-target sizes, and persistence rules so every screen implements them identically. Anything below tagged v1 ships in the first prototype; items tagged v2 are deferred but reserved.

01 · primary gestures

What touches do, region by region

Reading-mode requirement: the user can always pause without finding the play button. Tap-on-sky is load-bearing.
👆
Single tap · sky / viewport v1 · core
Toggle play ↔ pause
Works anywhere on the constellation viewport. The play button only confirms the state — it never has to be reached.
pointerup ≤ 250ms total move ≤ 8px debounce 100ms
👆👆
Double tap · sky v1
Snap playhead to live edge
Recovers from accidental scrubbing — returns to wherever the cinematic was last firing. Suppresses the single-tap pause that would otherwise trigger on the first tap.
2 taps ≤ 300ms apart centroid ≤ 24px
👈 👉
Horizontal swipe · sky v1
Scrub by roll
Each 56-px-wide swipe step = ±1 roll. A long swipe is a "throw" — keeps scrubbing with decay for up to 600ms after release based on release velocity.
|dx| ≥ 24px to engage |dx|/|dy| ≥ 1.5 step = 56px/roll throw decay 600ms
👆 👇
Horizontal drag · scrubber rail v1
Direct scrub by word position
Inside the mini-rail (portrait) and the cinema scrub pill (landscape), drag moves the playhead 1:1 with finger. Releases without snapping — current word position is preserved.
capture on rail only no momentum haptic on roll cross
🤏
Long press · roll dot v2
Preview tooltip
Hold a roll diamond on the scrubber to see "who fired / what perk / cp" without committing to a jump. Release to dismiss. Behaves like a hover on desktop.
≥ 450ms stationary move ≤ 6px during vibrate 8ms on lock
✋
Two-finger pinch · scrubber v2
Zoom time axis
Pinch on the scrubber rail to zoom in/out. Anchors the midpoint of the two touches to the timeline so the axis doesn't drift while pinching.
|Δ scale| ≥ 0.05 midpoint anchor clamp 1× – 8×
↓
Edge swipe from top · portrait v2
Reveal field log
Start within the top 36px and drag down to peel the field-log sheet over the sky. Drag-to-dismiss with the reverse gesture.
start < 36px from top |dy| ≥ 60px
🔄
Rotate device v1
Hand-off to landscape / portrait
Layout switches between Direction C (portrait) and Direction F (landscape). State persists — word position, play/pause, speed, on-roll behavior, mode all survive.
@media orientation no remount animate 220ms
02 · hit targets & touch ergonomics

Minimum reachable sizes

Apple HIG floor is 44×44 CSS px; Material is 48dp. We use 44 as the floor and bias toward 48–56 for repeatable controls (play, settings, scrub rail).

05 · ambiguity resolution

When two gestures could both fire

Predictable behaviour matters more than reactive cleverness. When in doubt, defer to the destructive-less gesture and require the user to be explicit about the destructive one.

Tap vs swipe

Finger moves < 8px during a quick contact — was that a tap or a tiny accidental swipe?

→ Treat as tap. Pause toggles; on accidental pause, the user re-taps. Far better than a 1-roll jitter scrub.

Tap vs double-tap

First tap pauses; second tap would jump to live. Do we wait 300ms before pausing?

→ Pause immediately on first tap. Double-tap snaps to live edge AND resumes playing; user perceives a single coherent action.

Sky swipe vs rail drag

Touch starts inside the scrub rail but moves up into the sky.

→ Capture wins. Whichever region got pointerdown owns the gesture until pointerup. The rail uses pointer-events: auto + capture; the sky listens only on its own bounds.

Long-press vs scroll

Holding still on the field-log panel for 450ms — is that a long-press or just slow reading?

→ Long-press is scoped to roll dots, not the log surface. A roll-card tap in the log is just a tap; long-press there is undefined.

Edge swipe vs system gestures

iOS reserves the bottom edge for the home indicator and the left edge for back-gesture.

→ All edge-swipes start ≥ 16px inside the safe area. The peek-sheet handle is centered and tall enough to be the affordance, not the OS edge.

Auto-hide chrome vs tap-to-pause

In landscape cinema with chrome hidden, a tap could either reveal chrome or pause.

→ Reveal first, tap-again pauses. If chrome is hidden, the first tap restores it (and resets the 4s timer). A second tap in that window pauses.

07 · accessibility & opt-outs

Quiet defaults, graceful overrides

The gesture contract must not become a usability trap. Every load-bearing gesture has a button equivalent. Every motion has a reduced-motion fallback.
  • Tap-to-pause opt-out. Settings → Comfort → "Tap to pause" toggle. When off, only the explicit FAB pauses. (Useful when a child is interacting and triggering pauses.)
  • Reduced-motion respect. If prefers-reduced-motion: reduce, throw-decay scrubbing is disabled; layout rotation skips the 220ms crossfade; the chrome auto-hide timer extends to 8000ms.
  • Haptics opt-out. Settings → Comfort → "Haptics". On by default if the device supports the Vibration API.
  • Keyboard equivalents. Space = pause/play, ←/→ = step roll, Home = live edge, ? = help. (Desktop primarily, but external keyboards on iPad use these too.)
  • Aria live region. Roll changes announce as "Roll 47 of 137. Atomic Reassembly, 800 CP." Screen-reader users get parity with the sighted "field log" feed.
  • Tap target floor. Nothing tappable smaller than 44×44 CSS px, ever. Visual diamonds may be smaller; tap zones extend.
  • Visible focus rings. Cyan 2px outline on keyboard focus; never outline: none without a replacement.
  • Help is one tap away. The "?" icon, the About flyout's "Gestures & help" link, and the landing-page help overlay all open the same help surface.

09 · open questions

Pinned for discussion

Things this spec doesn't settle yet — flagged here so the prototype defaults are obviously provisional.
  • Tap-to-pause off by default? Reads better but new users may not realize the sky is tappable. Prototype ships on; we can flip after testing.
  • Long-press preview vs jump. Currently long-press = preview, tap = jump. Should preview also commit on release-after-long, or only show?
  • Scrub direction. Swipe right = forward in time, swipe left = backward. Some users expect the opposite (pulling content). Pick one and stick.
  • Chrome auto-hide in portrait? Direction C keeps the mini-rail always visible. Should portrait also support a hide-chrome cinema mode, or is that landscape-only?
  • Throw-to-scrub. Inertia feels great but can overshoot dozens of rolls. Cap at +5 / -5 rolls per throw? Or trust velocity?
