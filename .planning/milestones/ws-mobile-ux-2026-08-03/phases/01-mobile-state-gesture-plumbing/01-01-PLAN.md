## Phase Goal

**Goal (ROADMAP Phase 1, verbatim):** The app knows which layout it is in and can receive touch gestures safely, with zero new UI and zero desktop change.

(The ROADMAP `**Goal:**` line is not in user-story format; it is carried verbatim rather than inventing a story. Mode is `mvp`; this plan is the tracer slice.)

<objective>
Tracer slice for Phase 1: prove the entire mobile plumbing stack end-to-end — layout-mode detection (D-06), the verbatim gesture-helper port with its per-render attach lifecycle (D-07, D-11), and the bcf:* storage schema bump (D-09) — wired through every layer this phase touches and verified by the existing Playwright harness, before any expansion work.

Purpose: the architecture risk of this phase is entirely in the wiring (script load order, matchMedia/CSS agreement, attach-without-double-bind, purge-on-bump). Proving one thin path through all of it first catches a dead-end after one commit instead of after four.

Output: `web/mobile-gestures.js` (byte-identical port), `web/app.js` layout/storage/gesture-lifecycle additions, `web/index.html` script + viewport meta per D-03, `tests/helpers/web_runtime_site.py` WEB_FILES extension, and `tests/test_mobile_plumbing.py` proving the slice.

MOBF-01 note: the interview gate is ALREADY SATISFIED — decisions D-01..D-11 are recorded in `01-CONTEXT.md`. This plan implements D-03/D-06/D-07/D-09/D-11; D-01 (mobile cinematic same as desktop), D-04 (Track B provenance shape), and D-05 (no mobile carousel in v1) are recorded decisions that bind later phases and require no Phase 1 code. Full-bleed cinematic and the plan §8 backlog items are deferred ideas and MUST NOT appear here.
</objective>

<assumption_delta_decision>
This phase pluralizes a singular: one layout path becomes three (desktop / portrait / landscape) selected by `app.layoutMode`. Decision: **add-alongside**, not promote-to-shared-abstraction. The desktop render tree is frozen (INTEGRATION_PLAN.md §0.1–§0.2; §7 explicitly forbids extracting shared components between desktop and mobile), so mobile renderers are added alongside as separate view code over the shared model — the `render()` branch on `app.layoutMode` is the only sanctioned touch point. This is an accepted, user-mandated decision. What would force a later promote: an explicit desktop unfreeze; until then no shared view abstraction may be extracted.
</assumption_delta_decision>
