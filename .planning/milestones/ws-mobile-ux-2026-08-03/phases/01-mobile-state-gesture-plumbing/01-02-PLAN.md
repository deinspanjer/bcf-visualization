## Phase Goal

**Goal (ROADMAP Phase 1, verbatim):** The app knows which layout it is in and can receive touch gestures safely, with zero new UI and zero desktop change.

<objective>
Expansion slice 1 over the proven tracer: land the mobile CSS foundation decisions (MOBF-05 — `touch-action`/`overscroll-behavior` surface classes, `svh`/`dvh` viewport primitives, `env(safe-area-inset-*)` custom properties, all made here so Phases 2-3 consume rather than retrofit them) and wire the D-02 pause-on-hidden behavior into the existing visibilitychange handler, mobile-only.

Purpose: CONTEXT.md mandates the CSS foundation decisions are made in Phase 1, not retrofitted; D-02 was missing from plan §6 acceptance and must land now so it cannot silently drop.

Output: `web/mobile.css` (new, linked and staged), the extended visibilitychange handler, and new test cases in `tests/test_mobile_plumbing.py` covering both.

Discretion resolution (CONTEXT "Claude's Discretion", CSS location): mobile CSS goes in a **separate `web/mobile.css`** loaded after `style.css`, not a new block inside `style.css`. Rationale: load order guarantees cascade victory over the pre-existing desktop-compaction blocks at style.css:1564/:1607 without ever touching the frozen file (RESEARCH Pitfall 5), and `git diff web/style.css` staying empty becomes a mechanical freeze check for every Track A phase.
</objective>
