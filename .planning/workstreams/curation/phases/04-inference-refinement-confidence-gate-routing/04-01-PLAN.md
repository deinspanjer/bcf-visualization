Build the transport spine as four modules. This task deliberately contains **no retrieval, no
grading, and no routing logic** — its job is to retire the integration risk before pipeline breadth
exists, exactly as `04-RESEARCH.md` §Q2 recommends.

Before writing anything, note what is deliberately absent. D-06's batch-submission client and
D-07's prompt-cache breakpoint are **struck by D-25** — neither is reachable through a subscribed
CLI transport, so build no batch client, no result-polling loop, and no cache-control plumbing.
D-08's *mechanism* is likewise gone, but **D-08's intent is non-negotiable and is what this task
implements**: the submission tool is the only delivery channel, and nothing anywhere may recover a
structured result by parsing the harness's free text.

`scripts/stage2_schema.py` — the three explicit JSON Schemas plus two version constants. This module
MUST NOT import `mcp`, so the schema guarantee stays testable without the optional extra installed.
Define `SUBMIT_STAGE2_ROLLS_SCHEMA`, `GET_PROSE_SPAN_SCHEMA`, `CHECK_QUOTE_SCHEMA`,
`STAGE2_TOOL_SURFACE_VERSION = "stage2-tools-v1"`, and `TOOL_NAMES` as a frozenset of exactly
`submit_stage2_rolls`, `get_prose_span`, `check_quote`. Every schema sets
`"additionalProperties": false`. `SUBMIT_STAGE2_ROLLS_SCHEMA` takes `chapter_num` (string),
and `rolls` (array); each roll object carries `slot_index` (integer), `outcome`, `constellation`,
`perks` (array of strings), `evidence_quotes` (array of objects with a required `text` and an
optional `mention_chapter_num`), `unfilled_fields` (array of strings),
`self_reported_confidence` (enum high/low) and `reasoning` (string). The roll object MUST NOT
accept `word_position`, `mention_word_position`, `source_ordinal`, `roll_number`, `confidence`,
or any key naming a destination — D-10 makes positions and ordinals code-derived, and D-26 forbids
the model choosing where output lands. `GET_PROSE_SPAN_SCHEMA` takes `chapter_num` (string),
`start_word` (integer, minimum 0) and `end_word` (integer, minimum 0). `CHECK_QUOTE_SCHEMA` takes
`chapter_num` (string) and `quote_text` (string, minLength 1). Use `{"type": "string"}` for
`chapter_num` everywhere — chapter numbers in this repo are strings like `"121.1"`.

`scripts/stage2_response.py` — the seam. Define a `Stage2Context` dataclass holding the warm objects
(`prose_loader` built with the `mechanical_verifier._build_prose_loader` closure shape,
`directory_index` from `perk_name_resolver.build_directory_match_index`, `obtained_perks_index` from
`mechanical_verifier.build_obtained_perks_index`, the overrides path, the proposals path, plus
per-chapter counters `prose_span_calls` and `check_quote_calls` and a `read_set` list), a
`RoutingOutcome` dataclass, and `process_stage2_response(chapter_num, rolls, *, ctx) -> RoutingOutcome`.
In this task the body records the submission on `ctx`, counts the rolls, and returns a
`RoutingOutcome` with `routed_to=None` — Task 3 fills the derive/verify/grade/route body without
changing this signature. `process_stage2_response` MUST be importable and callable with no MCP, no
subprocess and no transport; that is the structural rule that keeps everything downstream testable
with zero inference. Also define `ctx.begin_chapter(chapter_num)` and
`ctx.take_chapter_outcome(chapter_num)` so the Python caller can read handler-side state after the
subprocess returns. Give the module the sibling-import try/except fallback used by
`chapter_roll_overrides_io.py`.

`scripts/stage2_mcp_server.py` — the thin transport. Use `mcp.server.lowlevel.Server` (never
`FastMCP`'s signature-derived schema, which was measured coercing an integer `104` into the string
`"104"`). Register `@server.list_tools()` returning the three `types.Tool` objects with the explicit
`inputSchema` dicts from `stage2_schema`, and one `@server.call_tool()` dispatch that delegates:
`submit_stage2_rolls` calls `process_stage2_response(...)` and returns a text summary;
`get_prose_span` returns bounded prose via `ctx.prose_span(...)`; `check_quote` returns
`json.dumps(ctx.dry_run_quote(...))`. Leave `validate_input` at its default `True` — that flag is
what makes `jsonschema.validate` run at the boundary and return an `isError` correction signal, and
it is the entire reason D-26's guarantee holds. `ctx.prose_span` clamps to at most 400 CP-earning
words (a request for exactly 400 is served in full) and refuses the 6th call for a chapter with an
error result; `ctx.dry_run_quote` runs `mechanical_verifier._prose_search_text` plus
`_build_tier2_pattern` and returns `{found, tier, word_position, occurrence_count}`, refusing the
21st call for a chapter. Both read tools append `{tool, args, response_sha256}` to `ctx.read_set`
and MUST NOT record anything the confidence gate later consults, MUST NOT return any destination,
and MUST NOT read `chapter_roll_overrides.json`. The submission tool's text result must state what
was accepted and never where it went — if the model learns the destination, the next turn's
proposals get steered by it. Add `serve_warm_http(server, host, port)` starting the streamable-HTTP
transport, and `pick_ephemeral_port()`. Bind the loopback address only; never bind a wildcard or
all-interfaces address, and take the port from `pick_ephemeral_port()` so nothing is discoverable at
a fixed address.

`scripts/stage2_transport.py` — the mockable seam. Define the `Stage2Transport` Protocol with
`run_chapter(chapter_num, system_prompt, user_message, *, model) -> HarnessResult`; the
`HarnessResult` dataclass with `submitted: bool`, `submission: dict | None`, `turns`, `usage`,
`permission_denials`, `duration_ms`, `raw_envelope`; a production `ClaudeCliTransport` class; and a
`RecordedTransport` that returns a canned `HarnessResult` from a JSON fixture with no subprocess and
no network. The production class starts the warm server once, generates the per-run MCP config
`{"mcpServers": {"bcf": {"type": "http", "url": "http://127.0.0.1:<port>/mcp"}}}` as an inline JSON
string, and invokes the harness with `claude -p --strict-mcp-config --mcp-config <json>
--output-format json --model <model> --permission-mode dontAsk --tools "" --system-prompt <prefix>
--no-session-persistence --allowed-tools mcp__bcf__submit_stage2_rolls mcp__bcf__get_prose_span
mcp__bcf__check_quote`, with `timeout=180`. **Always pipe the prompt on stdin** — never pass it
positionally, because `--tools`, `--allowed-tools` and `--mcp-config` are variadic and swallow a
trailing positional argument, producing a misleading "Input must be provided" error. Use
`--permission-mode dontAsk`, which enforces the allowlist; `--permission-mode bypassPermissions` was
measured ignoring `--allowed-tools` entirely, which is the empirical proof that the server's exposed
tool set — not any CLI flag — is the security boundary. Never pass `--bare`: its own help text says
Anthropic auth becomes strictly `ANTHROPIC_API_KEY` or `apiKeyHelper`, which would silently defeat
D-25. Set `HarnessResult.submitted` from `ctx.take_chapter_outcome(chapter_num) is not None`, never
from `returncode`, never from `is_error`, and discard the envelope's `result` string entirely. Log
`permission_denials`, `num_turns` and the whole `usage` block as corroborating signals only. Shut
the server down in a `finally` block on every exit path.
