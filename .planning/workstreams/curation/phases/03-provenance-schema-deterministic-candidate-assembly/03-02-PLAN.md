<objective>
Build Stage 1: a deterministic, zero-LLM script that assembles candidate roll objects from machinery the pipeline already computes — `roll_text_evidence.json`'s anchors/prose-windows and `obtained_perks.json`'s paid-then-free bundle order — per ACUR-01 and ROADMAP success criterion 2.

**Revision note (this plan was corrected on 2026-08-01):** the binding rule below was originally gated on a roll's OWN row containing `"acquisition"`/`"miss"` in `matching_anchor_kinds`. Live measurement showed that gate lets only 36/718 rolls (5%) — and only 36/132 (27%) of the `direct` class — ever bind anything at all, because `matching_anchor_kinds` is scoped to a ±250-word window around each individual predicted roll, and the anchor catalog rarely lands there even on rolls with strong narrative evidence nearby (e.g. ch 92's hit and miss rolls both come back with `matching_anchor_kinds: []`). The corrected rule below fixes this: **binding is chapter-local POSITIONAL cursor advance through `merge_paid_units`'s default units — the primary binding signal — with `"acquisition"`/`"miss"` anchors used only to classify outcome and mark confidence, never to gate whether binding is attempted.**

For each of the 718 predicted rolls, walked chapter-by-chapter in narrative order (`predicted_word_in_chapter` ascending): if the row's own `matching_anchor_kinds` contains `"miss"`, classify it `outcome: "miss"` and do NOT consume a unit (bind constellation from a `constellation_reveal` anchor in `matching_events` if present, else null+unfilled). Otherwise, if the chapter's `merge_paid_units` unit cursor still has a unit available, consume it as a hit — perks = paid perk name + free ride-along names, constellation from the bound paid perk's own `constellation` field — REGARDLESS of whether that row's own `matching_anchor_kinds` contains `"acquisition"` (if it doesn't, mark `_derivation.unfilled_fields` with `"evidence_for:outcome"` to honestly flag the binding as positional-only, not anchor-confirmed). Otherwise (no unit left, no miss anchor), the roll is fully unfilled: `outcome: null`, `perks: []`, `constellation: null`. Separately — per CURATION-CONVENTIONS §2 — every bound hit gets a liberal forward search of the chapter for each free perk's name or substring, attaching the first mention as an additional evidence quote. Any part that can't be determined is marked unfilled, never guessed (D-06).

This plan is independent of Plan 03-01 (it never touches `chapter_roll_overrides.json`) and can run in the same wave.

Purpose: measure, before Phase 4 buys any inference, how far deterministic binding alone gets — Plan 03-03 scores this plan's output against the hand-curated corpus.
Output: `scripts/build_candidate_rolls.py`, `data/derived/_schemas/candidate_rolls.schema.json`, `data/derived/candidate_rolls.json` (gitignored, regenerable), `tests/test_build_candidate_rolls.py`.
