<objective>
Give `chapter_roll_overrides.json` a real schema-validation gate and make `curated_by` genuinely required, per CINF-01 and D-01/D-02/D-11/D-12.

Pattern mapping found the file has **no JSON schema at all** and is read via four independent `json.loads` call sites (`scripts/multi_grab.py:load_overrides`, `scripts/build_chapter_facts.py:_load_chapter_roll_overrides`, `scripts/forge_curator/data_loader.py`'s `chapter_roll_overrides` property, `scripts/forge_curator/persistence.py`). D-01 requires an absent `curated_by` to be a hard validation error, not a default — that has no hook to attach to until the four loaders are consolidated into one schema-validating function (D-11). This plan builds that function, stamps all 118 existing entries `curated_by: "human"`, rewires the four call sites to it, and fixes a real data-destruction bug this investigation found along the way: `forge_curator/persistence.py`'s `_load_or_default` currently swallows **any** exception (parse error or, after this change, schema-validation error) on an *existing* file and silently replaces it with an empty document — which the TUI's next save would then write back over the real 118-chapter corpus. This plan is a prerequisite for Plan 03-03 (candidate accuracy measurement), which reads the corpus through this same loader.

Purpose: make CINF-01's provenance marker load-bearing rather than decorative — a chapter entry can never again be silently treated as human-curated by omission, and a corrupted override file can never again be silently blanked.
Output: `data/derived/_schemas/chapter_roll_overrides.schema.json`, `scripts/chapter_roll_overrides_io.py`, `scripts/stamp_curator_provenance.py`, all 118 corpus entries stamped, all four consumers rewired, existing test fixtures updated for the new required field.
</objective>
