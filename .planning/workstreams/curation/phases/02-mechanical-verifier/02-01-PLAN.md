<objective>
Build the mechanical verifier's core: a shared, extracted CP-earning-word tokenizer (D-01/D-02) and `scripts/mechanical_verifier.py`'s `verify_roll()` — the pure, importable per-roll check covering all four of D-06's dimensions (evidence-quote text/position, word-position range, perk-name resolution, enum/structural sanity) — wired end-to-end against one real hand-curated roll from the live corpus, with a real runnable test proving the whole path works before any expansion happens.

Purpose: this is the phase's tracer bullet. Proving quote-match, position-tolerance, perk-ladder reuse, and enum sanity work together against real prose and a real curated roll — on the first task, before the corpus-wide loop or the CLI exist — catches an architectural mismatch (e.g. a wrong prose-loading contract, a broken char-offset mapping) while it costs one task to fix, not ten.

Output: `scripts/cp_word_index.py` (new), `scripts/mechanical_verifier.py` (new, `verify_roll()` core), `scripts/find_text_backed_rolls.py` (rewritten import block only), `tests/test_cp_word_index.py` + `tests/test_mechanical_verifier.py` (new).

Explicitly out of scope (D-07): roll-scheduling and slot-capacity validation. `verify_roll()` never checks whether a chapter's curated hits fit the predicted-roll slot count — that is `roll_scheduler.py`/`multi_grab.py` territory, and is exactly where chapter 104 currently fails (2 curated hits vs. 1 predicted slot, a Phase 1 deferred item this phase does not touch). This verifier only answers "is this curation internally truthful about the prose, positions, perk names, and enums?", never "does it fit the roll schedule?".
</objective>
