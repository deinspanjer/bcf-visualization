# Phase 2 — UI Design Contract: Portrait Layout

> Visual and interaction contract for `renderMobilePortrait()`. This document **locks** an already-approved design
> (`design/mobile-ux/prototype/layouts.jsx` `PortraitC`, `panels.jsx`, `styles.css`) into concrete values for the
> planner and executor — it does not invent new visual design. Generated by gsd-ui-researcher (autonomous session,
> `--auto`), verified by gsd-ui-checker.

## Spacing Scale

The prototype's approved visual design was authored as pixel-precise HUD chrome, not against a strict 8-point grid. Per this phase's mandate ("lock the existing design, don't invent a new one"), the values below are the **locked, sourced-from-prototype** pixel values. New mobile-only spacing not already dictated by the prototype/gesture-contract (e.g. any additional gap the executor must invent) MUST fall on the standard 8-point scale.

### Standard 8-point scale (use for anything not listed as a locked exception below)

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, `.seg` internal padding |
| sm | 8px | Chip/gap spacing (`.top-cluster` chip row gap), mini-rail internal padding |
| md | 16px | Default element spacing, flyout side padding |
| lg | 24px | Reserved — no lg-scale spacing needed in portrait v1 |
| xl | 32px | Reserved |
| 2xl | 48px | Reserved |
| 3xl | 64px | Reserved |

### Locked exceptions (verbatim from `design/mobile-ux/prototype/styles.css` — do not re-grid to 8pt)

| Element | Value | Source |
|---------|-------|--------|
| Tap target minimum | **44×44 CSS px** | D-14 requirement; `.icon-btn` (`min-width/min-height: 44px`); MOBX-03 project-wide floor |
| Compact icon button | 36×36 CSS px | `.icon-btn.compact` (speed cycle, gear, ⓘ, `?` in dock/top-cluster) |
| Play/pause FAB | 56×56 CSS px (portrait dock uses `.fab-play.md` = 46×46) | `.fab-play` |
| Chip padding | `5px 11px` | `.chip` |
| Top-cluster inset | `12px` from each edge | `.top-cluster` |
| Dock padding | `14px 12px` + `max(18px, env(safe-area-inset-bottom))` bottom | `.dock` (portrait `@media (orientation: portrait)` block) |
| Dock-transport gap | `10px` | `.dock-transport` |
| Mini-rail height | `70px`, internal padding `4px 8px` | `.mini-rail` |
| Cluster-bin merge threshold | `5px` (MOBP-04) | `MIN_DOT_SPACING_PX` in `scrubber.jsx` |
| Rail scrub step | `56px` per roll (gesture contract, MOBP-02/03) | `gesture-contract.html` `G.SCRUB_STEP_PX` |
| Flyout padding | `14px 16px` | `.flyout` |
| Flyout position (portrait) | `left/right: 14px`, `bottom: 152px` | `.flyout` portrait media rule |
| Help overlay padding | `max(20px, env(safe-area-inset-top))` top, `20px` sides, `max(20px, env(safe-area-inset-bottom))` bottom | `.help-overlay` |

**Sky/dock split:** `.sky { flex: 1 1 60%; min-height: 0; }` over `.dock { flex: 0 0 auto; }` inside a `.mobile-app` root using `flex-direction: column` — this is the MOBP-01 acceptance ratio, expressed via `flex-basis`, not a fixed height, so the dock's actual height is content-driven and the sky absorbs remaining space.

## Typography

Reuse the existing three-font HUD design language verbatim (already shipped and frozen on desktop) — the sizes below are the **locked** values from the approved prototype, grouped into 4 semantic roles per the design-contract format.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|--------------|-------|
| Micro-label (`--mono`) | 8–10px (chips/meta: 9–10px; group-labels/hint-row: 8px) | 400 | 1.3 | `.chip`, `.top-cluster`, dock `.now .meta`, `.hint-row`, `.flyout h4`, `.flyout .group-label`, `.seg button`, help-overlay `.label`/`h3` |
| Body (`--sans` default / `--serif` for narrative bits) | 11–13px (flyout `.row`/`.credit`: 11px; dock `.now .title`: 13px; help-overlay gesture list: 12px) | 400 | 1.4 | Flyout copy rows, dock now-title, About dataset stats, Help gesture-list body text |
| Heading (`--serif`) | 16px | 400 | 1.2 | `.flyout h2` ("Brockton's Celestial Forge"), `.help-overlay .credit-block .title` |
| Display (`--serif`, responsive) | `clamp(18px, 4.5vw, 26px)` (sky focal-label name); fixed 22px (help-overlay `h1`) | 400 | 1.15 | Sky cinematic focal label, Help overlay page title |

**Weights (exactly 2, per contract):**

| Weight | Value | Usage |
|--------|-------|-------|
| Regular | 400 | Default for all body/label/heading/display text (no element in the portrait surface sets an explicit non-400/700 weight) |
| Bold | 700 | CTA buttons only (`.got-it` "Got it — read on"), inline emphasis (`<b>` around "LordRoustabout", roll numbers), cluster-bin count badge numerals (`.roll-bin .count { font-weight: 700 }`) |

## Color

All values reused verbatim from `web/style.css:9-27` (frozen `:root` variables) — **never redefined** in `web/mobile.css` per CLAUDE.md's explicit instruction.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--void` (#03080d) / `--void-deep` (#02060a) radial+linear gradient | App shell background, sky viewport backdrop |
| Secondary (30%) | `--panel` / `--panel-strong` (rgba(5,29,38, 0.5–0.85)), `--edge` / `--edge-soft` (rgba(92,244,255, 0.08–0.56)) | Dock gradient overlay, mini-rail track, flyout/help-overlay surfaces, chip/icon-btn backgrounds and borders |
| Accent (10%) | `--cyan` (#5cf4ff) | **Reserved for:** play/pause FAB fill, active-roll diamond (`.roll-dot.active`), rail playhead + its end-caps, active `.seg`/`.icon-btn.is-active` state, "Got it" CTA button, focal-label glow/kicker text, focus-visible ring (new, D-16 focus trap) |
| Destructive | `--rose` (#ff8aa8) | **Semantic-state color, not an action-confirmation color** — reserved for "miss" outcome markers only (`.roll-dot.miss`, `.roll-bin.miss`, cluster count on a miss-dominant bin). This phase has **no destructive user actions** (no delete/remove/discard UI), so `--rose` never appears on a button or confirmation dialog in Phase 2. |

Second semantic color (non-destructive): `--green` (#7bffbd) — reserved for "hit" outcome markers only (`.roll-dot.hit`, `.roll-bin.hit`, `.sky-tap-hint` decorative pill) and the amber-adjacent roll-in-progress chip variant continues to use `--amber` (#f5d27b) for the default/pending roll-chip and roll-dot styling. Neither `--green` nor `--amber` is ever used on an interactive control — outcome-state color and interactive-accent color (`--cyan`) are kept strictly separate, matching the existing desktop convention.

**Accent reserved for (explicit list, nothing else):** play/pause FAB · active-roll diamond marker · rail playhead · active segmented-control option · active icon-button state · "Got it" help-dismiss CTA · focal-label glow text · new focus-visible outline on trapped-focus flyout elements (D-16).

| Error (all portrait surfaces) | Whole portrait surface | ✅ covered | Same pre-branch contract: `app.error` early-returns shared `renderLoadError()`. Reused unchanged this phase; no portrait-specific error copy/markup |

| Empty (unknown chapter) | Dock "now" title | ✅ covered | Falls back to literal `"—"` per Copywriting Contract |
| Empty (zero rolls in data) | Mini-rail | ✅ covered | `binRolls([])` returns `[]`; the rail renders chapter ticks + POV bands + playhead with no bins and no active diamond — no crash path (verbatim-port behavior) |
| Empty (no POV on chapter) | Hint row | ✅ covered | POV segment renders `{pov || "Joe"} POV` (default-POV convention per project chapter naming); zoom segment omitted entirely at 1× |
| Partial (missing roll fields) | Chips, mini-rail, flyouts | ✅ covered | Every data-driven text field has an explicit null fallback: `R{rollNumber ?? "—"}`, dock title `"—"`, About stats `{data?.rolls?.length || 0}` — no `undefined` ever renders |
| Long-text | Dock "now" title, dock meta line | ✅ covered | `white-space: nowrap; overflow: hidden; text-overflow: ellipsis` on both (`.dock-transport .now .meta`/`.title`, `styles.css:215-223`) — never wraps into a second line that could push the mini-rail down |
| Zero-one-many | Mini-rail cluster bins (MOBP-04) | ✅ covered | 1 roll → plain diamond; 2+ rolls within 5px → merged `.roll-bin` with numeric `.count` badge; active roll always rendered as a separate `.roll-dot.active` on top regardless of bin state |
| Populated (dominant outcome) | Cluster bin color | ✅ covered | `binRolls`/`finalizeBin` (verbatim port) assign the bin's dominant-outcome color (`hit`/`miss`/default-amber) per RESEARCH.md Pattern/Code-Examples section |
| Populated (normal playback) | All surfaces | ✅ covered | The default state is the contract itself — chips/dock/rail/flyout copy and tokens locked in the sections above |

Playwright bounding-box assertion at 320px AND real-device visual check (`test_portrait_layout_proportions_and_chip_overlap`, RESEARCH.md test map) |
| Overflow (sky letterboxing) | Sky camera at tall/narrow phone aspect | 🧪 backstop | `renderSkyCamera`'s `preserveAspectRatio="xMidYMid meet"` against a fixed 1.6:1 world-stage will letterbox at typical phone portrait aspect ratios — RESEARCH.md Assumption A1 explicitly defers "acceptable cinematic framing vs. looks broken" to the real-device Phase B gate review; do not pre-build a mobile-specific viewBox crop before that check |
| Overflow (short viewport) | Settings flyout / Help overlay | 🧪 backstop | At short portrait viewports (e.g. 320×568), the Settings flyout (`bottom: 152px` anchor) and Help overlay content must fit or scroll internally — needs a Playwright assertion that all controls remain reachable at 320×568 (flyout gets `max-height` + `overflow-y: auto` if it doesn't fit) |
| First-run help auto-open | Help overlay | 🧪 backstop | Trigger point ("after data load, mobile layouts only, once per session, when `helpSeen` is false") is Claude's Discretion per CONTEXT.md — needs a Playwright assertion, not just a visual check |
| Empty (static surfaces) | Settings flyout, Help overlay, About links | ✖ dismissed | Static control sets and fixed copy — no data-driven emptiness exists (the only data-driven About row, dataset stats, is covered under Partial above) |
| Zero-one-many (static collections) | Settings segments, Help gesture rows, About source links | ✖ dismissed | Fixed-cardinality collections defined by the contract (4/3/4-option segments, 7 gesture rows, 3 links) — cardinality cannot vary at runtime |
| Loading/error (per-flyout) | Settings/About/Help while open | ✖ dismissed | Flyouts read already-loaded in-memory state only (`app.*`, `data` stats); they are unreachable before data load (dock renders post-load) and perform no async work of their own |
